# Contributing to the Roomfile Style Atlas

The Atlas is a set of researched lenses for interior-design conversations. It
is not a style allowlist, a catalog of approved taste, or a fixed recipe.
User inspiration, reactions, constraints, and explicit preferences always
outrank Atlas signals. Unknown styles remain eligible for live research.

## Research checklist

- Define the label, its historical boundary, and its current social or
  commercial usage separately. Do not turn a recent market label into an
  ancient movement.
- Preserve each source's title, publisher, URL, source tier, kind, known
  publication date, retrieval date, and a short note stating what it supports.
- Use at least eight tier-1 records, five contemporary records, and three
  critical sources. Critical records must test canon formation, exclusions,
  marketing claims, cultural flattening, or other consequential misreadings.
- Paraphrase findings and cite source IDs. Do not copy source prose. Mark
  reading-only pages as rights-unclear for images unless a separate visual
  rights record has been verified.
- Cover origins, design logic, space, furniture and forms, materials, palette,
  lighting, textiles and art, density, variants, current expressions, room
  translation, and misreadings.
- Ask what the user means by the label. Record adopted, rejected, uncertain,
  and user-overridden signals rather than silently forcing a canonical look.

## Visual-rights checklist

- Start from the authoritative file page and verify its current rights
  statement. This release permits only `CC0-1.0`, `PDM-1.0`, and
  `CC-BY-4.0`. Reject NC, ND, SA, unclear, editorial-only, and
  platform-specific permissions.
- Fetch the verified direct-original URL sequentially. If the host throttles a
  large original, an authoritative derivative service from that same verified
  file page may be used with its acquisition URL and transformation recorded.
  Never import neighboring category images merely because one file passed
  review.
- Keep acquisition originals outside the repository. Create a local derivative
  capped at 1600 px on the long edge, with no unrecorded crop, retouching, or
  color reinterpretation. Record every transformation.
- Record source page, direct-original URL, creator, work title and date,
  institution, exact license, license URL, full attribution, retrieval date,
  derivative changes, byte size, dimensions, and SHA-256.
- Write specific alt text, an evidence-aware caption, what to notice, and
  what not to generalize. Attribution for CC BY work must name all roles and
  institutions requested by the source record.
- Identify historical Japanese, Danish, Finnish, or other cultural evidence
  precisely. Never relabel an antecedent object or room as historic Japandi.

## Quality and safety checklist

- Keep each quick guide between 800 and 1,200 English words and optimize it for
  agent decisions: definition, history/current distinction, strong signals,
  user questions, and clichés to avoid.
- Validate the production directory, recompute every local image SHA-256, run
  repository and portable-skill tests, run the privacy scan, and run
  `git diff --check`.
- Privacy is non-negotiable: do not add private user images, room facts,
  addresses, budgets, messages, or other personal data to an Atlas pack.
- Re-review time-sensitive media claims and license records before each
  release. A source's inclusion is evidence bookkeeping, not endorsement.
